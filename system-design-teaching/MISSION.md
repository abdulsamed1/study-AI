# Mission: System Design from Scratch

## Why
I am a junior backend/blockchain engineer preparing for system design interviews and need to understand architecture concepts to build production systems like Eagles (Workspace Rental Management System). Without system design knowledge, I cannot reason about scalability, reliability, or make informed architectural decisions in real projects.

## Success looks like
- Explain the components of any web system (load balancer, cache, database, queue) and why each exists
- Design a system like Eagles from scratch — justify every technology choice and data flow
- Pass system design interviews at mid-to-senior level companies
- Make architecture decisions in projects with confidence (not just follow tutorials)

## Constraints
- First time studying system design — start from fundamentals
- Backend/blockchain background — can leverage existing knowledge of databases, APIs, networking
- Learning alongside a real production system (Eagles) to ground theory in practice

## Out of scope
- Distributed systems theory (CAP theorem deep-dives, consensus algorithms) — practical design first
- Frontend architecture (React, CSS, component design) — backend/systems focus
- DevOps/infrastructure automation (Terraform, Kubernetes internals) — focus on design, not ops
